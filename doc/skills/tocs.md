# RpgTypes CS移植メモ

このメモはTypeScript製のライブラリであるRpgTypesをC#へ移植する際のメモです。

# RpgTypesの特徴

このライブラリは原則的に純粋関数を軸に作っています。

## eslintのルール

|ルール名|内容|h
|"@functional/no-return-void"|関数は戻り値を定義しなければならない
| "@functional/no-let"| letは禁止し、ローカル変数は全てconstで定義する
| "@functional/no-loop-statements"| for文は禁止し、できる限りreduceで定義する

一部のソースコードでではパフォーマンスの都合によりfor文を解禁している。
またreduceを使っている箇所はforへの置き換えによる高速化が容易なコードにしてある。

## テストコード

このプロジェクト全体で以下のようなテストコード管理をしている。
テストコードは本体コードの隣に置く。例えばfunc.tsがあるなら、同一フォルダ内にfunc.test.tsが配置されている。
テストが巨大になる場合、func.pattern.test.tsのような形で分割してある。

src/rmmzMock/以下のディレクトリには、ツクールMZのコアスクリプトをそのまま使用したテストコードが存在する。
これは純粋関数実装と、既存のコアスクリプトが同じ動作をしているか検証するテストである。
これらのテストコードは非常に巨大なため、そのまま読むとトークンを大量に消費してしまう。大半の実装はrmmzMockのテストコードを読まずに実装できるはずなので、できれば読まないこと。

## イベントコマンド

ツクールMZのイベントコマンドは、そのまま変換するとC#では不向きなデータ構造になっている。
そのため、C#移植の際はイベントコマンドを再設計する必要があるが、現時点では未着手である。
ただしテキスト抽出機能などもあるため、再設計の準備自体はできている。

# 実装済みの機能群

## features

ツクールMZ本体を利用する拡張機能群。
代表的なのはextract(テキストなどの抽出)とreplace(ゲーム内の文字列の置き換え)である。
これらはツール開発のバックエンドとして利用されている。

## fileio

ツクールのプロジェクトデータを解析するライブラリ。
注意してほしいのは、このライブラリは型定義が中心であること。
実際のファイル読み書きは別のライブラリで行う必要があり、依存性の注入によって解決させている。
テストコードはあるが、突貫工事のため情報不足になっている可能性がある。

## format

ツクールMZ用の新エディタを作るためのライブラリ。
別途features/format.mdがあるので、それを参考にすること。

## libs

外部ライブラリに依存している箇所と、RpgTypesで横断的に使う型をまとめたフォルダ。

## plugin

ツクールMZに存在する個別のプラグインを定義したSchema群。
汎用的に管理するのは困難なので、力業で全てを定義している。
workaroundとしての性質が強いので、無視してOK。

## rmmz

ツクールMZの型の内、JSONにデータとして記される型を扱ったライブラリ。
構成要素に含まれるのは、それらのデータを生成するFactory関数と、データだけで成立する関数の集合、様々な定数。
さらにこのフォルダは以下の層に分割されている。

### eventCommand

イベントコマンド各種を扱う。
それぞれのイベントコマンドを型として定義し、EventCommandは巨大なUnionになっている。
これらはツクールMZの構造をトレースすることが目的のため、C#移植では様々な修正が必要となる見込み。
UnionをそのままC#で実装するとvirtualが出現して実行コストが高くなるためである。

なおイベントコマンドを扱うデータ型は、コマンド部分をテンプレート化している。これは将来の差し替えに耐えられるようにするための準備構造である。

### rpg

RPG的なデータである装備品やアクターを扱うためのフォルダ。
大半がシンプルなデータのため、C#移植はしやすい。
ただ数値型の扱いが面倒だと思われる。

### script

ある文字列がスクリプトか否かを扱うためのフォルダ。
これはプラグイン由来の文字列を検証するために使われている。

### system

Data_Systemを扱うためのフォルダ。
用語と設定ファイルが混在しているため、非常に汚い状態になっている。
ただし、切り離すための処理はある程度実装してある。

### utils

その他の雑多なコード。あまり整理されてない。

## rmmzFunctional

ツクールMZの様々な実行時関数を純粋関数で再実装した関数群。
計算をメモ化することにより高速化を実現している。
このフォルダに置く関数の基準は以下の通り。
1:rmmzRuntimeの型を参照している。
2:使用している型がツクールMZの標準データ型に限られること

## rmmzMock

ツクールMZのコアスクリプトと、このライブラリの独自実装が同じ動作であることを検証するテストコード群。

## rmmzRuntime

ツクールMZ実行時の型を表現したinterface群。
ただし現時点では描画系は検証外となっている。

これらのinterfaceはRmmz\_(名詞)の形式で命名されている。

## rpgNext

将来的な設計を見据えた機能群。
従来のツクールMZはprototype書き換えによる混沌としたコードが問題のため、設計の修正が必要である。
それらを想定して、機能を作り直すための場所。ただし放置状態。

# CS移植の際の指針

C#用の型に変換する際、以下の方針を守ること

1:トップレベル型はclass
Game\_(固有名詞)・Rmmz\_(固有名詞)・Data\_(固有名詞)で命名されている型。これらはトップレベルの型であり、基本的にclassで扱うこと前提としている。

2:メンバが全てnumberかbooleanならstruct
配列の要素として使用されることが多いデータ。
TraitやItemEffectが該当する。メンバ数が4つ以内ならstructにしても引数にした際のコストが小さい。これらは実行中に書き換えない前提になっている。
ただし時々filterしている場合があるので、関数実装の際はLINQを組み合わせて低コストにすること。

## ゲームロジックの構築

ゲームロジックは完全新規実装で行う。
可能な限り純粋関数で実装することを目指し、各機能を整理中である。
特にバトルおよびイベントコマンドは再設計が決定済み。
